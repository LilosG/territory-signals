# Client configs

Each client gets exactly one YAML file in this folder, named `<client_id>.yaml`, with the shape shown in `kaiser-team.yaml`: `client_id`, `display_name`, a `territory` block (`planning_areas`, `zips`, `neighborhoods`), `owner_data_provider` (`sample` or `attom`), `team_members` (name, email, role, dre_license, phone; may be empty), `team_profile` (display_name, brokerage, office_address), `recipes` (recipe key -> `enabled`), and an `outreach` block (`mode`, `weekly_send_cap_per_agent`, `drafts_per_run`, `cooldown_days`, `approval_required_recipes`). The file is loaded and validated by `pipelines/territory/config.py`; unknown or invalid fields fail validation. One codebase serves every client, and each client gets its own deployment pointed at its own config.
